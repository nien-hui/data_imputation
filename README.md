Home Credit Feature Pipeline

Overview
- End-to-end workflow to build a single modeling table for the Home Credit Default Risk problem.
- Feature notebooks produce per-table aggregates into `transformed_data/` (one CSV per source table, keyed by `SK_ID_CURR`).
- `combine.py` loads `application_train.csv` and `application_test.csv`, drops the train label `TARGET`, concatenates them, then left-joins all CSVs in `transformed_data/` on `SK_ID_CURR` to produce `combined.csv`.

Repository Layout
- `home-credit-default-risk/` — raw Kaggle data: `application_train.csv`, `application_test.csv`, `bureau*.csv`, `credit_card_balance.csv`, etc.
- `transformed_data/` — feature tables generated by notebooks, e.g.:
  - `_bureau.csv`
  - `_bureau_balance.csv`
  - `_credit_card_balance.csv`
  - `_installments.csv`
  - `_pos_cash.csv`
  - `_prev_features.csv`
- Notebooks (exploration/feature engineering):
  - `credit_card_balance.ipynb`, `pos_cash_balance.ipynb`, `installments_payments.ipynb`, `bureau.ipynb`, `bureau_balance.ipynb`, `previous_application.ipynb`, `test.ipynb`
- `combine.py` — merges base applications with all transformed features.

What `combine.py` Does
1. Reads `home-credit-default-risk/application_train.csv` and `home-credit-default-risk/application_test.csv`.
2. Drops `TARGET` (label) from train to keep only features.
3. Coerces `SK_ID_CURR` to integer (`int64`) in both datasets (handles float-like IDs such as `100001.0`).
4. Aligns columns between train/test (union) and concatenates rows.
5. Scans `transformed_data/` for all `*.csv`, then for each file:
   - Drops stray index columns (e.g., `Unnamed: 0`).
   - Coerces and deduplicates `SK_ID_CURR`.
   - Left-joins on `SK_ID_CURR`.
   - If a feature column name already exists in the base, the right-hand column is suffixed with the file stem (e.g., `_credit_card_balance`).
6. Writes the final merged dataset to `combined.csv` in the project root.

How to Run
- Requirements: Python 3.8+ and `pandas`.
- Install: `pip install pandas`
- Execute: `python combine.py`
- Output: `combined.csv`

Notes & Tips
- The joins are left merges on `SK_ID_CURR`, so no base rows are lost even if some feature files lack a given ID.
- If a feature file has duplicate `SK_ID_CURR`, only the first occurrence is kept.
- If you add new feature CSVs to `transformed_data/`, re-run `combine.py` to include them automatically.

Troubleshooting
- Missing files: Ensure `home-credit-default-risk/application_train.csv` and `application_test.csv` exist.
- Key types: If `SK_ID_CURR` is non-numeric in a source, rows with invalid keys are dropped during coercion; check that file.
- Column collisions: Intentional suffixing prevents silent overwrites; adjust names in your feature CSVs if you prefer custom prefixes.
